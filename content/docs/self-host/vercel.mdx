---
title: Vercel
description: Hosted deployment considerations for this self-host-first fork.
---

This fork's verified production path is Docker Compose. Vercel deployment is not
the local deployment target documented or continuously validated here.

The current code no longer assumes Neon HTTP, Vercel Blob, or Vercel Sandbox:

- the database driver is `drizzle-orm/node-postgres`;
- uploads use local volume-backed storage;
- `run_code` uses Eve's Docker backend through a private socket proxy;
- model traffic uses the configured OpenAI-compatible `AI_GATEWAY_BASE_URL`.

A Vercel deployment would therefore need separate decisions for persistent file
storage, a PostgreSQL wire-protocol database reachable from functions, migration
execution, long-running Eve turns, and the Docker sandbox controller. Those
adaptations are not part of the verified Docker contract.

For a supported self-hosted deployment, use the [Docker guide](/docs/self-host/docker)
or the repository's
[operations runbook](https://github.com/thesobercoder/miniscira/blob/main/docs/DEPLOYMENT.md).

Vercel OAuth remains an optional identity provider when configured with
`VERCEL_CLIENT_ID` and `VERCEL_CLIENT_SECRET`; using it for sign-in does not make
the application itself dependent on Vercel hosting.
