---
title: Self-hosting
description: Run the full MiniScira stack locally with Docker Compose.
---

MiniScira ships a complete self-hosted Docker stack: the Next.js app, the Eve
agent runtime, PostgreSQL with pgvector, local upload storage, committed database
migrations, health checks, and durable named volumes.

## Architecture

The application image runs two supervised processes:

```text
Browser -> Next.js :3000 -> PostgreSQL
              |
              +-> /eve/v1/* -> Eve :4274 -> AI gateway
```

Both processes run in one container because the production rewrite targets
`127.0.0.1:4274`. `scripts/supervise.mjs` starts them as direct children. If
either one exits, the supervisor stops the survivor and terminates the container
so Docker's restart policy can recover the complete service.

## Quickstart

```bash
git clone https://github.com/thesobercoder/miniscira.git
cd miniscira
cp .env.example .env

# Fill in the required values, then:
docker compose build
docker compose up -d db
docker compose --profile migrate run --rm migrate
docker compose up -d app

curl http://localhost:3000/api/health
curl http://localhost:3000/eve/v1/health
```

Do not skip the migration step. Fresh databases receive the committed schema;
existing pre-migration databases are fingerprinted and baseline-stamped without
executing schema DDL.

## Required configuration

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL wire-protocol URL. The bundled service uses `pgvector/pgvector:pg16`. |
| `AI_GATEWAY_BASE_URL` | Base URL of an OpenAI-compatible gateway. There is no baked-in gateway fallback. |
| `BETTER_AUTH_SECRET` | Session/authentication secret. Generate a strong random value. |
| `BETTER_AUTH_URL` | Browser-facing origin, such as `http://localhost:3000`. |

The Compose database credentials must match the password embedded in
`DATABASE_URL`. Set `AI_GATEWAY_API_KEY` and `ALLOW_SHARED_GATEWAY_KEY=true` when
the deployment should provide one shared gateway credential; otherwise users
can save their own gateway keys in Settings.

## Models

`DEFAULT_CHAT_MODEL` is optional. Docker Compose forwards it to both the image
build and runtime so the browser and server agree. Rebuild the image after
changing it.

`AI_MODELS_JSON` is optional display metadata only. The live gateway `/v1/models`
catalog remains authoritative and metadata cannot add unavailable models.
Malformed metadata fails at the container entrypoint before Eve or Next starts.

## Storage and migrations

- `miniscira-db` persists PostgreSQL data.
- `miniscira-uploads` persists local files under `/data/uploads`.
- Normal app startup does not mutate the schema.
- `docker compose --profile migrate run --rm migrate` applies committed Drizzle
  migrations.
- `RUN_DB_PUSH=true` is a transitional, opt-in compatibility gate; leave it
  disabled for normal operation.

## Sandbox

`run_code` and the Bash tool use Eve's `just-bash` backend. Commands execute as
ordinary subprocesses inside the application container. This is deliberately
local and requires no Vercel account or Docker socket, but it is **not**
container-level isolation from the application.

## Optional capabilities

Search, social login, lookout email, and image-generation features activate only
when their corresponding environment variables are configured. See
`.env.example` and the repository's [deployment runbook](https://github.com/thesobercoder/miniscira/blob/main/docs/DEPLOYMENT.md)
for the complete matrix, backup/restore procedures, upgrades, rollback, reverse
proxying, and troubleshooting.

## Platform note

The default image target is `linux/amd64`. `@firecrawl/pdf-inspector` currently
has no native Linux ARM64 binding, so ARM hosts must run the amd64 image under
emulation rather than using a native ARM64 build.
