The repository's `Dockerfile` and `docker-compose.yml` are the canonical local
deployment path. The Compose stack includes the application, PostgreSQL with
pgvector, a one-shot migration service, durable volumes, and health checks.

## Start a fresh stack

```bash
cp .env.example .env
# Fill in DATABASE_URL, AI_GATEWAY_BASE_URL, BETTER_AUTH_SECRET,
# BETTER_AUTH_URL, and matching POSTGRES_PASSWORD.

docker compose build
docker compose up -d db
docker compose --profile migrate run --rm migrate
docker compose up -d app
```

Starting the database and applying migrations before the app makes first boot
deterministic. Normal app startup never runs unrestricted schema changes.

## Image contents

The multi-stage image:

- installs dependencies with Bun;
- builds both Eve and Next.js with Node;
- copies Eve's `.output/` bundle and the Next.js output;
- includes `content/`, `source.config.ts`, and `next.config.ts` so `/docs` works;
- includes committed Drizzle migrations and runtime scripts;
- includes Python, pandas, NumPy, and Matplotlib for local `run_code` tasks;
- starts through `scripts/entrypoint.mjs` and `scripts/supervise.mjs`.

The entrypoint validates required configuration, rejects malformed
`AI_MODELS_JSON`, waits for PostgreSQL, honors the opt-in `RUN_DB_PUSH` gate, and
then starts Eve and Next under supervision.

## Health and process supervision

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/eve/v1/health
```

The container health check probes both routes. A healthy result means Next.js,
PostgreSQL access, Eve, and the internal rewrite are all operational. If either
Eve or Next exits, the supervisor terminates the container so
`restart: unless-stopped` restarts the complete pair.

## Database and uploads

The bundled database is `pgvector/pgvector:pg16`. MiniScira uses
`drizzle-orm/node-postgres`, so ordinary PostgreSQL wire-protocol URLs work.
Named volumes preserve database data and uploads across container recreation:

```yaml
volumes:
  miniscira-db:
  miniscira-uploads:
```

Use the migration profile for both fresh installations and upgrades:

```bash
docker compose --profile migrate run --rm migrate
```

Existing databases from before committed migrations are validated and stamped
as the baseline without running schema DDL.

## External PostgreSQL

For a managed or separately hosted pgvector-capable database:

```bash
docker compose -f docker-compose.yml -f docker-compose.external-db.yml build
docker compose -f docker-compose.yml -f docker-compose.external-db.yml \
  --profile migrate run --rm migrate
docker compose -f docker-compose.yml -f docker-compose.external-db.yml up -d app
```

The override requires Docker Compose v2.20+ and uses Compose's `!reset` tag to
remove the bundled database and both database dependencies. Set `DATABASE_URL`
to the external server before rendering the configuration.

## Gateway and models

All model traffic goes through `AI_GATEWAY_BASE_URL`; no LAN address, hosted
provider, or `host.docker.internal` fallback is baked into the image.

The gateway's live `/v1/models` response determines availability.
`AI_MODELS_JSON` may rename, hide, annotate, or order those models, but cannot
invent models. `DEFAULT_CHAT_MODEL` is optional and is forwarded to the Docker
build and runtime; rebuild after changing it.

## Local sandbox

The sandbox is the intentional `just-bash` backend. It executes subprocesses
inside the app container and requires neither Vercel Sandbox credentials nor a
Docker socket. It is not Docker-level isolation; do not expose the application
to untrusted users on the assumption that `run_code` has a separate container.

## Platform support

Use the default `linux/amd64` image target. Linux ARM64 is not currently a native
supported build because `@firecrawl/pdf-inspector` lacks a Linux ARM64 native
binding. ARM hosts can use amd64 emulation.

## Verify the deployment

```bash
docker compose ps
docker compose logs app
curl -i http://localhost:3000/sign-in
curl -i http://localhost:3000/docs
curl -i http://localhost:3000/api/health
curl -i http://localhost:3000/eve/v1/health
```

An unauthenticated `/eve/v1/info` request should return `401`, not `200`.
