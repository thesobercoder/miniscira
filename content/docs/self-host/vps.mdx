title: VPS
description: Run the Docker Compose stack on a local server or VPS.
---

A VPS, home server, or spare amd64 machine can run the same canonical Docker
Compose deployment. There is no separate systemd-only architecture to maintain.

## Prerequisites

Install Docker Engine and Docker Compose v2.20 or newer. On ARM hardware, enable
amd64 emulation because the current image cannot build natively for Linux ARM64.

## Deploy

```bash
git clone https://github.com/thesobercoder/miniscira.git /srv/miniscira
cd /srv/miniscira
cp .env.example .env

# Configure the required environment values.
docker compose build
docker compose up -d db
docker compose --profile migrate run --rm migrate
docker compose up -d app
```

The bundled `pgvector/pgvector:pg16` service is suitable for a single-host
installation. For managed PostgreSQL, use `docker-compose.external-db.yml` as
described in the Docker guide.

## Reverse proxy

Expose only port 3000 from the app. Do not publish Eve's internal port 4274.

```text title="/etc/caddy/Caddyfile"
miniscira.example.com {
  encode zstd gzip
  reverse_proxy 127.0.0.1:3000
}
```

Set `BETTER_AUTH_URL` and `APP_URL` to the public HTTPS origin and add any other
trusted browser origins to `BETTER_AUTH_TRUSTED_ORIGINS`.

For nginx, disable response buffering and allow long-lived streams:

```nginx
proxy_buffering off;
proxy_read_timeout 900s;
```

## Persistence and backups

Back up both named volumes before upgrades:

- PostgreSQL: use `pg_dump -Fc` against the `db` service.
- Uploads: archive `/data/uploads` from the app service.
- Save the current Compose configuration and image digest for rollback.

The full commands and restore order are documented in
[`docs/DEPLOYMENT.md`](https://github.com/thesobercoder/miniscira/blob/main/docs/DEPLOYMENT.md).

## Upgrade

```bash
cd /srv/miniscira
git pull
docker compose build
docker compose --profile migrate run --rm migrate
docker compose up -d app
```

Do not run `db:push` as a routine upgrade step. The one-shot migration service
uses the committed migration history.

## Verify

```bash
docker compose ps
docker compose logs --tail=200 app
curl -fsS https://miniscira.example.com/api/health
curl -fsS https://miniscira.example.com/eve/v1/health
curl -sS -o /dev/null -w '%{http_code}\n' \
  https://miniscira.example.com/eve/v1/info
```

The health endpoints should return `200`. The unauthenticated info endpoint
should return `401`.

## Security boundary

`NODE_ENV=production` is set by the container image and must not be overridden.
The app talks to the host Docker daemon through a private socket-proxy sidecar;
the raw socket is never mounted into MiniScira and the proxy port is not
published. Sandbox containers start with Docker networking disabled. This is a
practical personal-deployment boundary, not a hardened multi-tenant runtime.
